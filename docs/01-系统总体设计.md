# 01 · 系统总体设计

## 一、系统定位

AI Business Flow 是一个**业务流程知识管理平台**——将散落的业务文档自动抽取为结构化 YAML（主流程 · 决策树 · 异常矩阵），同时支持从零开始通过对话式梳理构建业务流程。

**核心差异化**：市面上大多数知识库提取自然语言文本，本项目提取的是**可直接执行的结构化 YAML**，可直接驱动业务系统。

## 三、数据流向

### 方式一：文档抽取（有文档时）

```
用户上传 .md 文档
       │
       ▼
  processes/{id}/documents/   ← 文件存储
       │
       ▼
POST /api/extraction/{id}/extract
       │
       ├── 1. 读取文档内容
       ├── 2. 加载 business-flow-skill Prompt 模板
       ├── 3. LLM Client 调用（统一 transport）
       ├── 4. 解析 YAML 输出
       │
       ▼
生成四个文件：
  ├── main.yaml              ← 主流程步骤（职责分工 + SLA）
  ├── decision-tree.yaml     ← 决策节点和分支逻辑
  ├── exceptions.yaml        ← 异常处理矩阵
  └── extraction-report.md   ← 置信度报告
```

### 方式二：对话式梳理（无文档，从零开始）

```
用户切换到 DialogueTab（发起对话）
       │
       ▼
POST /api/query/dialogue/{id}
       │
       ├── 每次对话追加写入
       │   processes/{id}/dialogue_history.json
       │
       ├── 对话完成（is_complete=true）后
       │   ├── 生成 main.yaml / decision-tree.yaml / exceptions.yaml
       │   └── extracted_data 写入 knowledge.json
       │
       ▼
GET /api/processes/{id}/knowledge
       │
       ▼
KnowledgeTab 展示 YAML 内容
```

## 四、模块职责一览

### 前端（Next.js）

| 模块 | 文件 | 职责 |
|------|------|------|
| 流程列表 | `ProcessList.tsx` | 列表、新建、删除业务流程 |
| 流程详情 | `ProcessDetail.tsx` | 三 Tab 布局容器 |
| **配置弹窗** | `SettingsDialog.tsx` | 32 Provider 下拉选择、连接测试、YAML 保存 |
| 文档标签 | `DocumentTab.tsx` | 本地文件上传、远程路径配置 |
| **知识标签** | `KnowledgeTab.tsx` | 展示 4 个 YAML 文件内容 |
| **对话标签** | `DialogueTab.tsx` | 对话 UI + 文件持久化历史加载 |

| 模块 | 文件 | 职责 |
|------|------|------|
| **LLM Provider 注册表** | `llm_config.py` | 32 个 Provider 的定义、别名、env var、base_url |
| **配置加载** | `config.py` | `llm_config.yaml` 读写、环境变量覆盖解析 |
| **统一 LLM Client** | `services/llm_client.py` | 四种 transport 的工厂类 |

| **知识抽取** | `routers/extraction.py` | AI 编排器，调用 LLM Client |
| **对话问答** | `routers/query.py` | 对话 + 历史文件读写 |
| **入口** | `main.py` | CORS 配置 + 23 条 API 路由注册 |

## 五、关键设计决策

### 1. LLM 配置三层优先级

```
用户界面配置（YAML 文件）
        ↓
环境变量覆盖（API Key / Base URL）
        ↓
代码默认值（llm_config.py 中的 hardcoded 值）
```

设计原则：**从不暴露credentials到代码中**——所有敏感信息均在 YAML 或环境变量层处理。

### 2. 统一 LLM Client 的四种 Transport

| Transport | API Mode | 代表 Provider |
|-----------|----------|--------------|
| `openai_chat` | `chat_completions` | OpenRouter, DeepSeek, Gemini, HuggingFace... |
| `anthropic_messages` | `anthropic_messages` | Anthropic, MiniMax |
| `codex_responses` | `codex_responses` | OpenAI Codex, xAI, Copilot ACP |
| `bedrock_converse` | `bedrock_converse` | AWS Bedrock |

### 3. 对话历史文件持久化

```
DialogueTab mount
    │
    ├── GET /api/query/dialogue/{id}/history
    │       ← 读取 processes/{id}/dialogue_history.json
    │
    ▼
每次对话后（非完成）
    │
    └── POST /api/query/dialogue/{id}
            ← 追加写入 dialogue_history.json

对话完成（is_complete=true）
    │
    ├── 生成 YAML 文件
    └── extracted_data 写入 knowledge.json
```

### 4. has_knowledge 判断

知识结构 Tab 是否展示，看是否存在**任一**以下文件：

```
processes/{id}/
├── main.yaml
├── decision-tree.yaml
├── exceptions.yaml
└── extraction-report.md (或 knowledge.json)
```
